# Фронтенд NEXUS AI

Пользовательский интерфейс на Laravel 12, Blade и Livewire 3. Alpine.js уже
поставляется вместе с Livewire — не подключайте вторую копию. Авторизация
работает через стандартный веб-сеанс Laravel и Fortify.

## Локальный запуск

1. Откройте папку `frontend/` в PhpStorm. В **Settings → PHP** укажите
   локальный интерпретатор PHP (в текущей установке XAMPP:
   `C:\xampp\php\php.exe`) и Composer PHAR
   (`%LOCALAPPDATA%\Composer\composer.phar`). Если IDE не обнаружила Node.js
   автоматически, задайте путь к установленному Node.js.
2. Если `.env` ещё нет, скопируйте `.env.example` в `.env`. Файл `.env`
   игнорируется Git и должен оставаться локальным. Укажите `APP_URL`, затем
   параметры локальной MySQL: `DB_CONNECTION=mysql`, `DB_HOST`, `DB_PORT`,
   `DB_DATABASE`, `DB_USERNAME` и `DB_PASSWORD`. Сначала создайте базу данных.
   Не помещайте ключи NEXUS AI в настройки браузера.
3. Установите зависимости и примените миграции к локальной базе:

   ```powershell
   composer install
   npm install
   php artisan key:generate
   php artisan migrate --seed
   npm run build
   ```

4. Запустите приложение в терминале PhpStorm:

   ```powershell
   php artisan serve
   ```

   Для разработки стилей запустите `npm run dev` во втором терминале. Откройте
   `http://127.0.0.1:8000`.

## Вход и роли

Публичная регистрация отключена. Для первоначальной настройки администратора
задайте в локальном `.env` переменные `NEXUS_ADMIN_NAME`,
`NEXUS_ADMIN_EMAIL` (адрес для входа) и `NEXUS_ADMIN_PASSWORD` (не менее
16 символов), затем выполните `php artisan migrate --seed`. Сидер создаёт или
обновляет эту учётную запись и назначает ей роль `admin`; при повторном запуске
сида пароль администратора синхронизируется со значением в `.env`.

После 15 минут без реальных действий пользователя интерфейс отправляет запрос
выхода, сервер инвалидирует сеанс, а браузер переходит на главную страницу
(`/`), которая для гостя открывает вход. Таймер учитывает ввод, указатель,
клавиатуру, прокрутку и касания; фоновые запросы и polling его не продлевают.
Сервер независимо проверяет idle-срок на защищённых маршрутах, поэтому
клиентский таймер не является единственной защитой. Если вкладка была
заморожена браузером, истечение проверяется сразу при её возвращении на экран.

## Подключение NEXUS AI

Администратор может открыть **Эксперты** в боковой панели. Laravel получает
каталог с `GET /v1/experts/all`. В локальном `frontend/.env` задайте
`NEXUS_AI_URL` как base URL, доступный PHP-процессу, включая префикс reverse
proxy, если он есть. Например, для стандартного NEXUS AI proxy это
`http://31.128.38.96/api`; Laravel добавляет к адресу пути `/v1/...`, включая
список документов `/v1/projects/{id}/documents`. Переменная
`NEXUS_AI_ADMIN_KEY` используется только
сервером для admin-only каталога и никогда не передаётся в браузер.

В разделе **Назначение проектов** администратор связывает Laravel-пользователя
с UUID проекта NEXUS и его project API key. Laravel хранит ключ в БД через
encrypted cast; после сохранения он не отображается и не возвращается в HTML.
Перед каждым запросом чата проект выбирается только из назначенных пользователю
записей. Laravel проксирует `POST /v1/chat/stream` с project key и передаёт SSE
по мере чтения, без буферизации; NEXUS AI автоматически выбирает доступных
экспертов по сообщению. Отправка чата разрешена ролям admin/user, viewer имеет
только доступ для чтения. Для длинных ответов задаётся
`NEXUS_AI_STREAM_TIMEOUT` (по умолчанию 900 секунд). Admin API key никогда не
используется для пользовательского чата. В администраторском окне вопроса по
документу Laravel использует серверный admin API key для `POST /v1/chat/stream`,
ограничивает RAG выбранными `project_id` и `document_ids` и передаёт SSE без
буферизации. На странице документов можно выбрать до 10 готовых файлов проекта
для общего RAG-анализа; перед запуском Laravel проверяет принадлежность каждого
файла проекту и его статус через FastAPI. Этот ключ не попадает в браузер.

### Ключи внешних приложений

Внешний ключ можно выпустить из админки без AWS. После выпуска полный ключ
однократно показывается администратору, чтобы скопировать его в защищённую
конфигурацию целевого приложения. Для POST/Redirect/GET Laravel держит ключ в
session только зашифрованным; первый GET `/admin/projects` извлекает его и
сразу удаляет из session. Страница имеет заголовки `Cache-Control: no-store`
и `Pragma: no-cache`. Полный ключ не сохраняется в основной БД или логах.
После ухода/обновления страницы ключ нельзя открыть повторно: его нужно
отозвать и выпустить новый.

Для дополнительной автоматической доставки включите
`APPLICATION_KEY_DELIVERY_ENABLED=true` только после выдачи Laravel IAM role с
правами `secretsmanager:CreateSecret`, `secretsmanager:TagResource`,
`secretsmanager:DescribeSecret` и `secretsmanager:DeleteSecret` для заданного
префикса. Регион задаётся через `AWS_DEFAULT_REGION`, префикс имён — через
`APPLICATION_KEY_SECRET_PREFIX`. В production используйте IAM role среды
выполнения и не задавайте долгоживущие AWS access keys в `.env`.

При включённой AWS-доставке Laravel дополнительно сохраняет секрет в AWS
Secrets Manager. В локальной таблице `external_application_secrets` хранятся
только ID проекта/ключа, имя приложения и ARN для учёта жизненного цикла; сам
секрет туда не записывается.
При отзыве сначала отключает ключ в NEXUS AI, проверяет ownership-теги секрета
и ставит его на безвозвратное удаление через 7 дней. Секрет становится
недоступен для чтения сразу после постановки на удаление; восстановить его можно
только через AWS в течение recovery window, но сам NEXUS-ключ уже отозван.
Если сохранение при выпуске не удаётся, Laravel отзывает только что созданный
ключ; если очистка AWS или отзыв не удаются, сообщает администратору, что
требуется ручная проверка. Удаление проекта через Laravel блокируется, пока
остаётся секрет, доставленный этим приложением; отзовите управляемые ключи в
карточке проекта, чтобы очистить секреты перед удалением проекта.
Приложению-получателю назначьте отдельную IAM role с `secretsmanager:GetSecretValue`
только на выданный ARN. Секрет имеет JSON-поля `api_key`, `project_id`, `key_id`
и `application_name`. Имя ресурса строится как
`{APPLICATION_KEY_SECRET_PREFIX}/projects/{project_id}/applications/{key_id}`.

На странице **Пользователи** администратор может создать учётную запись и
назначить ей роль `admin`, `user` или `viewer`. Система создаёт случайный
временный пароль и показывает его администратору однократно после создания.
Передайте пароль пользователю безопасным способом; при первом входе ему нужно
задать новый пароль, прежде чем пользоваться остальными разделами.

Доверенный оператор также может изменить роль уже существующего пользователя
командой:

```powershell
php artisan app:assign-user-role you@example.com admin
```

Административный экран и создание пользователей защищены проверкой роли и
разрешением `manage-users`. Публичная регистрация отключена. Доступ к каждому
проекту проверяется по привязке Laravel-пользователя перед показом страницы и
перед каждым запросом чата; администратор назначает проекты на отдельной
защищённой странице.

Письма для восстановления пароля отправляются через настроенный почтовый
транспорт Laravel. В локальной конфигурации `MAIL_MAILER=log` ссылка сброса
записывается в `storage/logs/laravel.log`.

Тесты всегда используют отдельную временную SQLite в памяти и не подключаются
к MySQL из `.env`:

```powershell
php artisan test
```

Панель остаётся отдельным Laravel-приложением, которое обращается к NEXUS AI
только через серверный API-клиент; задайте `NEXUS_AI_URL` для нужного
окружения, чтобы включить живые запросы.
