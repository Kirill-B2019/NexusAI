# NEXUS AI — UI / Панель управления

Целевое руководство для пользовательского интерфейса NEXUS AI на Laravel 12,
Blade, Livewire и Alpine.js. Laravel-приложение пока не создано.

## Философия

NEXUS AI остаётся отдельным API-first FastAPI-сервисом и не навязывает UI.
Пользователи, сессии, роли и авторизация — ответственность Laravel.
Изменения Laravel ограничиваются интеграциями, нужными интерфейсу; не переносите
в него логику и ответственность NEXUS AI.

Не используйте React, Vue или отдельную SPA без явного решения пользователя.
TypeScript допустим только для изолированной браузерной логики SSE-чата на
`fetch` и `ReadableStream`. Реализуйте интерфейс небольшими вертикальными шагами,
следуя Laravel-паттернам; объясняйте важные решения и при необходимости кратко
объясняйте изучаемые концепции.

## Роли и доступ

Роли хранятся в Laravel:
- admin — полный доступ к админ-панели и всем проектам
- user — работа со своими проектами
- viewer — только чтение

Laravel → NEXUS AI проксирует запросы с admin или project API-ключом.
UI никогда не получает API-ключ NEXUS AI или другие секреты.
Выпуск API-ключей внешним приложениям остаётся отключённым, пока не настроена
одобренная сервер-сервер интеграция передачи секрета; не создавайте ключ,
который невозможно безопасно доставить. UI может показывать только метаданные
ключей (префикс, область экспертов, срок, статус и время последнего использования).

## Экраны админ-панели

### /admin/dashboard

Источник: GET /v1/admin/stats

Показывает:
- Карточки: проекты, документы (ready/failed), чанки
- Диалоги, сообщения, решения, задачи
- API-ключи (активные / всего)
- Эксперты (включено / всего)
- Аудит за 24ч (всего / chat-запросов)

Вёрстка: сетка 4×2 с карточками KPI.

### /admin/experts

Источник: GET /v1/experts/all (admin). Каталог, описания и значения формы редактирования загружаются из ответа NEXUS AI; Laravel их локально не хранит.

Карточки показывают иконку, имя, описание, системный статус, состояние и ключевые слова. Действие «Изменить» открывает форму с данными сервера: ключ только для чтения, имя, описание, system prompt, keywords, иконка, цвет, sort order и is_enabled.

Создание отправляется на POST /v1/experts; изменения — PATCH /v1/experts/{key}. Laravel преобразует введённые через запятую keywords в список и отправляет только поля, разрешённые схемами ExpertCreate и ExpertUpdate. Идентификатор системного эксперта нельзя изменить. Удаление доступно только для экспертов с is_system=false и выполняется через DELETE /v1/experts/{key}.

### /admin/training/datasets

Административный экран для ручных Q/A-пар экспертов. Laravel загружает данные
экспертов и партий из FastAPI, принимает JSONL или CSV не более 50 МБ и 50 000
строк, а файл сервер-сервер проксируется на FastAPI без передачи API-ключа в
браузер. Предпросмотр отображает ошибки валидации, обнаруженные дубли и первые
50 примеров.

Формат импорта версионируется (`format_version = 2`), контракт задан в
`api/dataset_validation.py`:
- **JSONL, прямой формат** — записи вида `{"question", "answer"}`; опциональные
  поля `topic`, `labels`, `note`, `source_id` и любые прочие top-level ключи
  переносятся в `metadata` примера, как и дополнительные столбцы CSV.
- **JSONL, legacy-формат** — `messages` с ролями user/assistant (system
  необязателен). Нормализация в пару question/answer явная: каждая строка
  помечается `source_format` (`qna` / `messages` / `csv`), а system prompt не
  отбрасывается молча, а сохраняется в `metadata.system_prompt` и попадает в
  snapshot.
- **CSV** — обязательные столбцы `question` и `answer`, остальные столбцы
  уходят в `metadata`.
Все ошибки возвращаются с номером строки, кодировка — UTF-8.

Дубликаты ищутся внутри файла и среди более ранних партий того же эксперта со
статусом «ожидает проверки» или «утверждена». Перед утверждением партии с дублями
администратор должен явно подтвердить, что проверил кандидатов; автоматического
удаления похожих вопросов нет.

Импорт идемпотентен в пределах партии: повторная загрузка того же файла для того
же эксперта (совпадает sha256) не создаёт дубль, а открывает существующую партию
и показывает уведомление «Такой файл уже загружен». Ограничение накладывает
частичный unique-индекс
`uq_training_dataset_batches_expert_source` (см.
`scripts/migrations/20261017_training_dataset_batch_idempotency.sql`);
отклонённые партии из индекса исключаются, поэтому тот же файл можно загрузить
заново после отклонения.

Администратор может утвердить корректную партию или отклонить её. Утверждение
создаёт неизменяемый snapshot в PostgreSQL и фиксируется в журнале аудита; оно
не запускает LoRA-обучение и не меняет работающую модель. Обнаруженные дубли
нужно просмотреть вручную перед утверждением.

Пока партия в статусе «ожидает проверки», её строки можно править прямо на
странице проверки, не перезагружая файл:
- в списке «Ошибки строк» для строки с расхождением `metadata.expert` есть
  кнопка «Привязать к {expert}» (PATCH с исправленным `metadata`);
- для строки, не прошедшей разбор, показывается форма с вопросом и ответом —
  она превращает ошибочную строку в корректный пример;
- у каждой ошибочной строки и у каждого примера в таблице предпросмотра есть
  кнопка «Удалить строку» с подтверждением.

После PATCH или DELETE Laravel возвращает администратора на ту же партию,
сообщает об успехе и показывает пересчитанные счётчики: некорректные строки
перестают блокировать утверждение. Редактирование и удаление фиксируются в
журнале аудита, а утверждённая партия и release-снимок остаются неизменяемыми.

При выборе эксперта (query-параметр `?expert=`) страница показывает блок
«Прогресс набора данных»: число утверждённых пар относительно цели по темам,
прогресс по каждой теме и подсказку «Не хватает тем: …». Тема примера
определяется по полю `topic` в метаданных, иначе — по ключевым словам вопроса;
цели по темам заданы в `api/training_topics.json`. Для эксперта без конфигурации
тем блок сообщает, что список тем не задан. Если API ещё не отдаёт статистику,
блок не показывается — страница работает как раньше.

Секция «Снимки датасета эксперта» собирает **release** — неизменяемый снимок
уровня эксперта из всех его утверждённых партий: состав `batch_ids`, число
примеров, sha256 содержимого, `format_version` и параметры подготовки
(`prep_params`). Операция доступна через POST /v1/admin/training/datasets/releases
и фиксируется в аудите; если утверждённых партий нет, API отвечает 409 и ошибка
показывается в форме. Изменить созданный снимок нельзя — только собрать новый.
Этот release — целевой вход для будущего обучения LoRA.

Секция «Реестр LoRA-адаптеров» управляет версиями обученных адаптеров
эксперта. Загрузочная форма принимает эксперта, базовую модель (например
`Qwen3-4B`), необязательный release-снимок из выпадающего списка, файл `.gguf`
(до 256 МБ) и заметку; файл проксируется на POST /v1/admin/training/adapters
без передачи ключа в браузер. Локально отклоняются файлы не `.gguf` и пустая
`base_model`; прочие ошибки приходят с API и показываются тем же способом, что
и при импорте партий.

Повторная загрузка того же файла (совпадает sha256) не создаёт дубль — API
возвращает существующую версию и UI показывает уведомление «Адаптер уже
загружен». Таблица реестра показывает для каждой версии: эксперта и номер
версии, статус (`candidate` / `published` / `archived` / `rolled_back`),
базовую модель, первые 12 символов sha256, размер, дату и действия:
«Опубликовать» (кандидат или прошлая версия → `published`, ровно один
опубликованный адаптер на эксперта), «Откатить» (только активный →
`rolled_back`) и «Удалить» (нельзя опубликованный — сначала откат), каждое с
подтверждением. Уведомления об успехе: «Адаптер загружен» (+ номер версии),
«Адаптер уже загружен», «Адаптер опубликован», «Публикация отменена»,
«Адаптер удалён»; конфликты (409) показываются текстом ошибки API.

Обучение выполняется на внешнем GPU — реестр хранит и публикует готовый
`.gguf`, не запуская обучение и не перезапуская модель. Публикация меняет
только реестр; применение адаптера на inference-сервере — отдельный шаг
оператора (см. `docs/OPERATIONS.md`).

Секция «Черновики из интернета» собирает кандидаты Q/A из веб-поиска. Форма
принимает эксперта, поисковый запрос (3–500 символов) и число пар (3/5/10);
запрос проксируется на POST /v1/admin/training/research — поиск и вызов модели
выполняются на стороне API, ключ поискового провайдера в браузер не попадает.
Черновики возвращаются в UI как редактируемые пары `вопрос`/`ответ` с
привязанным источником и списком найденных ссылок (свёрнутый блок «Источники»).
Форма также принимает необязательное поле «Тема»: выбранная метка сохраняется в
метаданных каждой пары и учитывается при подсчёте покрытия.

Администратор правит пары прямо в таблице, отмечает чекбоксами «Принять» нужные
и нажимает «Принять и включить в обучение»: Laravel собирает JSONL только из
отмеченных пар и отправляет его обычным импортом партии. Принятие сразу означает
утверждение: если в партии нет ошибок и возможных дублей, Laravel автоматически
утверждает партию (snapshot) и собирает новый release, поэтому принятые пары
попадают в самый свежий снимок датасета, из которого обучается эксперт. Если
найдены некорректные строки или дубли, партия остаётся «ожидает проверки» и
проходит ручной путь (правка строк, дубли, утверждение, release). Запуск
обучения на GPU по-прежнему выполняется отдельно. Кнопка «Отменить черновики»
очищает несохранённые пары. Ошибки показываются полем формы: `404` — эксперт
недоступен, `422` — поиск не нашёл источников, `502` — модель не составила
пары, `503` — поиск недоступен (по умолчанию работает бесплатный провайдер
`wikipedia` без ключа; `brave` требует `BRAVE_SEARCH_API_KEY`). Черновики
хранятся в сессии между запросами и не пишутся в БД до подтверждения.

### /admin/projects

`/admin/projects` показывает компактный список проектов из GET /v1/projects: название, описание, назначенного пользователя и ссылку «Открыть настройки». Создание проекта скрыто в сворачиваемой форме, чтобы список оставался основным фокусом. Каталог не загружает ключи и каталог экспертов.

`/admin/projects/{id}` — настройки выбранного проекта: назначение пользователя и состояние внутреннего ключа Laravel, внешние API-ключи, редактирование данных и быстрые ссылки на документы, разговоры, решения и задачи. После проектных операций администратор остаётся на странице этого проекта; после выпуска внешний секрет показывается там один раз.

**Два разных типа ключей — не смешивать в интерфейсе:**
- **Внутренний ключ чата Laravel** создаётся при создании проекта или назначении пользователя, хранится в Laravel зашифрованным и используется сервером. Он не показывается и не передаётся пользователю. Действия: назначить пользователя, выпустить или заменить ключ чата.
- **API-ключ внешнего приложения** создаётся через POST /v1/projects/{id}/keys с ограничениями по советникам (чекбоксы), лимиту запросов и окну действия `starts_at`–`expires_at`. Пустое начало означает немедленную активацию, пустое окончание — без срока. Запланированный ключ отклоняется API до наступления `starts_at`. Полный ключ показывается авторизованному администратору ровно один раз, чтобы скопировать его в секреты целевого приложения. Для POST/Redirect/GET он хранится в Laravel session только в зашифрованном виде и удаляется при первом GET страницы; ответ страницы имеет `Cache-Control: no-store`. Отзыв использует DELETE /v1/projects/{id}/keys/{key_id}.
- AWS Secrets Manager — дополнительная автоматическая доставка: при включённом `APPLICATION_KEY_DELIVERY_ENABLED` ключ сохраняется в AWS и локально учитываются только метаданные ARN/жизненного цикла. Без AWS администратор переносит ключ в менеджер секретов целевого приложения вручную.
- Выпуск, просмотр списка и отзыв доступны только роли администратора (`manage-users`). Список показывает маскированный префикс, активность, срок, ограничения и последнее использование; полный секрет не сохраняется в основной БД или логах и не возвращается API списка ключей.
- При обновлении существующей PostgreSQL-базы до версии API с окном действия применить миграцию `scripts/migrations/20261016_add_api_key_starts_at.sql` до развертывания новой версии сервиса.

Быстрые ссылки из карточки открывают документы, разговоры, решения и задачи выбранного проекта.

**Стрим:**

Для браузерного SSE-чата используйте изолированную логику на TypeScript с
`fetch` + `ReadableStream`. Запрос идёт только к Laravel-прокси; CSRF-токен
передаётся по правилам Laravel, API-ключа NEXUS AI в браузере нет:

- Enter отправляет сообщение; Ctrl+Enter вставляет новую строку.
- Ответ каждого эксперта можно скопировать в буфер обмена.
- История ответа прокручивается внутри области беседы, поле ввода остаётся видимым.

    const response = await fetch('/nexus-proxy/chat/stream', {
      method: 'POST',
      headers: {
        'X-CSRF-TOKEN': csrfToken,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({ message, expert, project_id })
    });

    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    let buffer = '';

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      buffer += decoder.decode(value, { stream: true });
      const events = buffer.split('\n\n');
      buffer = events.pop();

      for (const ev of events) {
        const type = (ev.match(/^event: (.+)$/m) || [])[1];
        const data = (ev.match(/^data: (.+)$/m) || [])[1];
        if (!data) continue;
        const payload = JSON.parse(data);

        if (type === 'token') {
          appendToActiveExpert(payload.expert, payload.delta);
        } else if (type === 'expert_start') {
          startExpertBlock(payload.expert);
        } else if (type === 'done') {
          finalize(payload);
        }
      }
    }

### /app/projects/{id}/documents

Источник: GET /v1/projects/{id}/documents

Действия:
- Drag & drop загрузка → POST /v1/projects/{id}/documents
- Список с фильтром по status

## Проксирование через Laravel

UI не общается с NEXUS AI напрямую.
До реализации сверяйте используемые endpoint'ы, параметры и ответы с фактическими
FastAPI-роутерами: документация может расходиться с кодом. Laravel хранит ключи
только на сервере, применяет сессионную авторизацию и проксирует SSE без
буферизации. Настройте подходящие connect/read/upstream и reverse-proxy таймауты
для долгих ответов, отключите буферизацию (включая `X-Accel-Buffering: no`) и
передавайте события клиенту по мере получения.

**Laravel роуты:**

    // routes/web.php
    Route::middleware(['auth', 'admin'])->prefix('nexus-proxy')->group(function () {
        Route::get('/admin/stats', [NexusProxyController::class, 'adminStats']);
        Route::get('/admin/experts', [NexusProxyController::class, 'adminExperts']);
        Route::patch('/admin/experts/{key}', [NexusProxyController::class, 'adminExpertUpdate']);
        Route::get('/admin/audit', [NexusProxyController::class, 'adminAudit']);
        Route::get('/admin/system-health', [NexusProxyController::class, 'adminSystemHealth']);
    });

    Route::middleware('auth')->prefix('nexus-proxy')->group(function () {
        Route::post('/chat', [NexusProxyController::class, 'chat']);
        Route::post('/chat/stream', [NexusProxyController::class, 'chatStream']);
        Route::get('/projects/{id}/documents', [NexusProxyController::class, 'listDocuments']);
        Route::post('/projects/{id}/documents', [NexusProxyController::class, 'uploadDocument']);
    });

**NexusProxyController:**

    class NexusProxyController
    {
        public function adminStats()
        {
            return Http::withHeaders(['X-API-Key' => config('services.nexus_ai.admin_key')])
                ->get(config('services.nexus_ai.base_url') . '/v1/admin/stats')
                ->json();
        }

        public function chat(Request $request)
        {
            $project = $request->user()->currentProject();
            return Http::withHeaders(['X-API-Key' => $project->nexus_api_key])
                ->timeout(180)
                ->post(config('services.nexus_ai.base_url') . '/v1/chat', $request->all())
                ->json();
        }
    }

## Реализация интерфейса

- Разметку и серверно-управляемые состояния реализуйте на Blade и Livewire.
- Используйте Alpine.js для небольших локальных интеракций; не создавайте на его
  основе отдельное SPA.
- TypeScript-модуль допускается только для парсинга/обработки браузерного SSE
  чата через Laravel-прокси (`fetch` + `ReadableStream`), без секретов NEXUS AI.

### Структура Laravel UI

Размещайте пользовательский интерфейс в `frontend/` и добавляйте структуру
постепенно, когда она нужна:

```text
frontend/resources/views/
├── layouts/                 # Основные layouts приложения и авторизации
├── pages/                   # Полноценные страницы
├── components/
│   ├── ui/                  # Общий набор визуальных компонентов
│   └── layout/              # Sidebar, topbar и навигация
└── livewire/                # Шаблоны компонентов Livewire

frontend/app/Livewire/       # PHP-классы Livewire, когда они нужны
```

Компоненты `components/ui/` образуют общий UI Kit: button, field/input, select,
checkbox, badge, card, alert, modal, table, pagination, empty state и toast.
Группируйте классы Livewire по областям Auth, Admin и Projects только по мере
появления соответствующей функциональности; не создавайте пустые каталоги и
слои заранее.

### UI Kit, визуальная система и доступность

- Перед созданием нового компонента сначала найдите подходящий существующий
  компонент UI Kit. Новый повторно используемый паттерн добавляйте в набор;
  избегайте дублирующей разметки, разрозненных вариантов и одноразовых CSS-решений.
- Централизуйте варианты и визуальный стиль общих компонентов. Цвета, шрифты,
  интервалы, радиусы, тени и состояния фокуса храните как общие токены в
  `frontend/resources/css/app.css`.
- Поддерживайте единый тёмный визуальный стиль и адаптивность для мобильных
  экранов.
- Используйте семантическую разметку, связанные с полями подписи, клавиатурную
  навигацию и видимый фокус. Модальные окна должны поддерживать Escape,
  управление/возврат фокуса и блокировать взаимодействие с фоном, пока открыты.

### Blade, Livewire и JavaScript

- Используйте Blade-компоненты для повторно используемых презентационных
  элементов, Livewire — для интерактивных страниц и форм с серверным состоянием,
  Alpine.js — только для лёгкого локального поведения.
- Не добавляйте встроенные CSS/JavaScript или внешние CDN-зависимости; не
  подключайте второй экземпляр Alpine.js поверх Livewire.
- Соблюдайте Laravel conventions для именования и именованных маршрутов,
  группируйте middleware по уровню доступа.

### PHP, авторизация и проверки

- Соблюдайте PSR-12 и форматируйте PHP через Laravel Pint.
- Оставляйте контроллеры тонкими; входные данные валидируйте через Form Request,
  авторизацию реализуйте через Policies и Gates.
- Выносите бизнес-логику в сервисы только при наличии реальной общей
  ответственности, требующей такого слоя.
- Добавляйте feature-тесты для авторизации, RBAC и CRUD-сценариев. Проверяйте
  относящиеся к изменениям тесты и запускайте `npm run build`.
- Сохраняйте локальный `frontend/.env` и его секреты; изменяйте только при
  необходимости и никогда не добавляйте этот файл в Git.

## Рекомендации

1. **Стрим — обязательно.** Ответ от эксперта может идти 2-5 минут на CPU. Без стрима пользователь думает, что система зависла.

2. **Показывайте источники RAG.** Это ключевая ценность — ответ на основе документов проекта.

3. **Отключайте RAG для общих вопросов.** В чате — чекбокс RAG.

4. **Разные цвета для экспертов.** Пользователь сразу видит, кто что сказал.

5. **Отдельный экран «Аудит» для админа.** Это журнал всех действий.

6. **Согласуйте таймауты на всём пути SSE.** На CPU thinking-ответ может занять
   4–5 минут; настройте клиент, Laravel, upstream и reverse proxy соответственно.

7. **Показывайте rate limit.** Заголовки X-RateLimit-Remaining — пользователь видит, сколько осталось.

8. **Логируйте X-Request-ID.** Если что-то упало — по нему можно найти в audit_log.

9. **Проксируйте через Laravel.** Не давайте UI прямой доступ к NEXUS AI — все ключи на сервере.

10. **Кэшируйте список экспертов.** Он редко меняется, можно раз в 5 минут.
